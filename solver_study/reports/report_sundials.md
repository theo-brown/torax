
# SUNDIALS v7.9.0 design choices relevant to TORAX (1D stiff nonlinear transport, N = 100–800, JAX/CPU)

All paths are relative to `/home/user/sundials`. Line numbers are from the v7.9.0 checkout (`CMakeLists.txt`: `PACKAGE_VERSION 7.9.0`).

Notation: `WRMS` = weighted root-mean-square norm, `||v||_WRMS = sqrt( (1/N) Σ (v_i w_i)^2 )` with `w_i = 1/(rtol·|y_i| + atol_i)` (`src/cvode/cvode.c:4896-4903`; `doc/cvode/guide/source/Mathematics.rst` eq. `CVODE_errwt`). `U` = unit roundoff (2.2e-16 double). "TORAX assessment" paragraphs are my judgement given: N tiny, extremely stiff NN transport, JAX fixed-shape `while_loop`s with explicit carries, CPU, compile time matters.

---

## 0. Executive summary (what actually transfers to TORAX)

1. **The error estimate is free.** CVODE's local error estimate is `dsm = tq[2] · ||acor||_WRMS`, where `acor = y_corrected − y_predicted` is the final Newton correction (`src/cvode/cvode.c:3458`). For backward Euler (q = 1) the coefficient is `tq[2] = 1/2` (derived from `cvSetTqBDF`, `cvode.c:3061-3063`). TORAX already has a predictor (explicit Euler is exactly CVODE's q = 1 Nordsieck predictor, `cvode.c:2792-2799`) and a corrector, so `LTE ≈ 0.5·||y_{n+1} − (y_n + dt·f(y_n))||_WRMS` costs nothing extra. This removes TORAX's biggest structural gap ("NO local error estimate").
2. **Newton is cheap in SUNDIALS because the Jacobian is lagged, capped at 3 iterations, and stopped on the *update* norm with a convergence-rate estimate, not a residual norm.** CVODE: `NLS_MAXCOR = 3`, `CRDOWN = 0.3`, `RDIV = 2.0` (`src/cvode/cvode_nls.c:32-34`); J re-evaluated at most every `msbj = 51` steps unless a failure occurs (`src/cvode/cvode_ls_impl.h:43`), matrix re-factored at most every `msbp = 20` steps or when `|γ/γ̄ − 1| > 0.3` (`src/cvode/cvode_impl.h:66-68`). TORAX recomputes a dense `jacfwd` Jacobian (N JVPs) at *every* Newton iteration; SUNDIALS' amortised cost is ≈ (bandwidth)/51 function evaluations per step for the Jacobian plus 1–3 residual evaluations.
3. **Structure exploitation:** CVODE's banded difference-quotient Jacobian needs `mupper + mlower + 1` function evaluations by Curtis–Powell–Reid column grouping (`src/cvode/cvode_ls.c:1192-1253`). For TORAX with C channels and cell-major ordering the half-bandwidth is `2C − 1`, so 15 seeded JVPs (C = 4) replace N = 100–800 JVPs. Global couplings (Gaussian smoothing) must be frozen in J (modified Newton tolerates this) or handled by a low-rank correction; CPR grouping is *unsafe* with true global couplings (it aliases far-column contributions into band entries).
4. **Failure handling is step-size-based, not line-search-based.** No SUNDIALS *integrator* uses a line search; on Newton divergence/non-convergence the step is cut by `η_cf = 0.25` (CVODE `ETA_CF_DEFAULT`, `cvode_impl.h:94`; IDA `ida_impl.h:67`; ARKODE `ETACF`, `arkode_adapt_impl.h:56`) and the Jacobian is refreshed. TORAX halves dt only after a full Newton failure and backtracks inside Newton; SUNDIALS' divergence detection (`||δ_m||/||δ_{m−1}|| > 2`) aborts after one bad iteration.
5. **Algebraic rows → IDA semantics:** exclude algebraic components from the error norm (`IDASetSuppressAlg`, `N_VWrmsNormMask` with the `id` vector, `src/ida/ida.c:3503-3512`), refresh J when `cj/cj_old ∉ [0.6, 1.667]` (`dcj = 0.25`, `ida.c:2753-2759`), and compute consistent initial conditions with `IDACalcIC` (Newton + Armijo line search, `α = 1e−4`, halving, ≤100 backtracks; `src/ida/ida_ic.c:46-47, 569-601`).
6. **Positivity:** `CVodeSetConstraints` clamps the solution if the violation is below the Newton tolerance and otherwise reduces the step by `η = 0.9·min-quotient` (`cvode.c:3197-3320`). Direct template for T_e, T_i, n_e > 0.
7. **Second-order, L-stable, embedded one-step alternatives** that keep TORAX's "one step at a time" structure: ARKODE's default 2nd-order implicit table `ARKODE_GKC21_ESDIRK_3_1_2`, and `ARKODE_TRBDF2_3_3_2` (`include/arkode/arkode_arkstep.h:60`, `include/arkode/arkode_butcher_dirk.h:40,61`). Theta = 0.5 (Crank–Nicolson) is A- but not L-stable; the repo's own guidance says "either cap BDF order at 2 or move ... toward an appropriate DIRK table" for parabolic problems (`.agents/skills/sundials-guide/SKILL.md`, section 2).
8. **Anderson acceleration** for TORAX's 'linear' (Picard/predictor-corrector) mode: `SUNNonlinSol_FixedPoint` implements Walker–Ni AA with a QR-updated least-squares problem and optional damping (`src/sunnonlinsol/fixedpoint/sunnonlinsol_fixedpoint.c:545-737`); memory 5 + 3m vectors, all fixed-shape — JAX-friendly.
9. **Super-time-stepping (LSRKStep RKC/RKL, ExtSTS)** targets exactly "diffusion-dominated, real-eigenvalue" stiffness, with stage count `s ≈ sqrt(1 + 1.53·h|λ|)` (RKC), but it evaluates the NN transport `s` times per step and only reaches 2nd order. With N ≤ 800 and cheap JAX Jacobians, an implicit step is cheaper; STS is only attractive if Jacobian/linear solves must be avoided entirely.
10. **Adjoints:** SUNDIALS' *discrete* adjoint (SUNAdjointStepper) requires fixed steps and explicit RK (`src/arkode/arkode_arkstep.c:3588-3607, 3689-3694`); CVODES uses a *continuous* adjoint with checkpointing. For JAX-AD through an adaptive controller, accept/reject and step-size decisions should be treated as non-differentiable constants (stop-gradient) — SUNDIALS' fixed-step restriction is the same constraint in disguise.

## 1. CVODE/CVODES BDF: variable-order, variable-step machinery

### 1.1 Norm, tolerances, Nordsieck array, predictor
- Error weights: `cvEwtSetSS` (`src/cvode/cvode.c:4879-4907`): `ewt_i = 1/(rtol·|y_i| + atol)`; vector-atol variant at `4919-4947`. If `atol_min = 0`, any non-positive weight aborts (`4899-4902`).
- State is a Nordsieck array `zn[j] = h^j y^{(j)}/j!`, `j = 0..q` (`src/cvode/cvode_impl.h:225-228`), plus `tau[1..q+1]` past step sizes (`276-277`), `tq[1..5]` test quantities (`278-279`), `l[0..q]` (`280`).
- **Predictor** `cvPredict` (`cvode.c:2779-2803`): repeated additions `zn[j-1] += zn[j]` (Pascal-triangle extrapolation of the interpolating polynomial to `t_n + h`). For q = 1 this is `y_pred = y_n + h f(y_n)`. The Newton correction starts at `acor = 0` (`cvode.c:3127`), i.e. the initial guess is exactly the predictor.
- Step-size change rescales `zn[j] *= η^j` (`cvRescale`, `cvode.c:2749-2767`); `cvRestore` undoes prediction after any failure (`3408-3421`).

### 1.2 BDF coefficients and test quantities (`cvSetBDF`, `cvSetTqBDF`, `cvode.c:2994-3085`)
- `tq[2] = |A1/(α0·A2)|`, `A1 = 1 − α̂0 + α0`, `A2 = 1 + q·A1` (`3061-3063`); `tq[5]` (`3064-3065`) is used for order-increase estimates; `tq[1]`, `tq[3]` only when `qwait == 1` (`3066-3083`).
- **`tq[4] = nlscoef / tq[2]`** (`3084`) is the tolerance passed to the nonlinear solver.
- Worked values (constant step): q = 1 → `α0 = α̂0 = −1`, `A1 = 1`, `A2 = 2`, **`tq[2] = 0.5`**, `tq[4] = 0.2`. q = 2 → `α0 = α̂0 = −1.5`, `A1 = 1`, `A2 = 3`, **`tq[2] = 2/9 ≈ 0.222`**, `tq[4] ≈ 0.45`.

### 1.3 Local error test (`cvDoErrorTest`, `cvode.c:3452-3536`)
- `dsm = acnrm · tq[2]` (`3458`), `acnrm = ||acor||_WRMS` (computed inside the convergence test, `cvode_nls.c:380`). Accept iff `dsm ≤ 1` (`3462`). Doc: `||Δ_n||_WRMS ≤ ε ≡ 1/|C'|` ("Local Error Test").
- On failure: `netf++`, restore, and if `nef ≤ MXNEF1 (=3)`:
  `η = 1/((BIAS2·dsm)^{1/L} + ADDON)`, `L = q+1`, `BIAS2 = 6`, `ADDON = 1e−6` (`3483`; constants `cvode_impl.h:107-109`), then `η = max(η_min_ef = 0.1, η, hmin/|h|)` (`3484-3486`), and if `nef ≥ small_nef (=2)` additionally `η = min(η, η_max_ef = 0.2)` (`3487-3490`). Doc: `(h'/h)^{q+1}||Δ_n|| = ε/6` ("1/6 is a safety factor").
- After more than `MXNEF1 = 3` failures: order reduced by one with `η = max(0.1, hmin/|h|)` (`3500-3511`); at order 1: restart from scratch with a fresh `f` evaluation and `qwait = LONG_WAIT = 10` (`3516-3535`).
- Give up after `maxnef = MXNEF = 7` failures or at `|h| ≤ hmin·(1+1e−6)` (`3471-3475`; `cvode_impl.h:128`, `ONEPSM 1.000001` at `:97`).

### 1.4 Step-size selection after success (`cvPrepareNextStep`/`cvSetEta`/`cvChooseEta`, `cvode.c:3618-3799`)
- If `etamax == 1` (a failure happened earlier in this step attempt) → no change, `qwait = max(qwait, 2)` (`3621-3627`).
- Same-order candidate: `η_q = 1/((6·dsm)^{1/L} + 1e−6)` (`3631`).
- `cvSetEta` (`3667-3696`): **if `η_min_fx (=0) < η < η_max_fx (=1.5)` then `η = 1` (keep h)**; otherwise growth is capped by `etamax` and `hmax`; shrink bounded below by `η_min = 0.1` and `hmin`. Consequence: after a *successful* step CVODE never *decreases* h (η_min_fx = 0) and only grows it if the estimate says ≥ 1.5×.
- `etamax` schedule (`cvStep`, `2505-2507`): `ETA_MAX_FS = 10000` on the first step, `ETA_MAX_ES = 10` while `nst ≤ SMALL_NST = 10`, `ETA_MAX_GS = 10` afterwards (`cvode_impl.h:88-90, 95`). After any error-test or convergence failure `etamax = 1` (`3380`, `3478`).
- Quantitatively for BDF1: `dsm = 0.1 → η_q = 1.29` → step *kept*; growth requires `dsm < 1/(6·1.5²) ≈ 0.074`; a failed step with `dsm = 2` gives `η = 0.29`.

### 1.5 Order selection (`cvode.c:3640-3799`)
- Order changes considered only when `qwait == 0`; after a change `qwait = L = q+1` (`cvAdjustParams`, `2536-2560`); after a decision `qwait = 2` (`3645`).
- `η_{q−1} = 1/((BIAS1·ddn)^{1/q} + ADDON)`, `ddn = ||zn[q]||_WRMS·tq[1]`, `BIAS1 = 6` (`3705-3718`).
- `η_{q+1} = 1/((BIAS3·dup)^{1/(L+1)} + ADDON)`, `dup = ||acor − cquot·zn[qmax]||_WRMS·tq[3]`, `BIAS3 = 10` (`3727-3744`), `cquot = (tq[5]/saved_tq5)·(h/tau[2])^L` (`3735-3736`).
- `cvChooseEta` (`3758-3799`): `η = max(η_{q−1}, η_q, η_{q+1})`; ties prefer keep > decrease > increase; if the max is inside the fixed band, keep order and `η = 1`.
- `qmax = BDF_Q_MAX = 5` (`cvode_impl.h:56`); integration starts at q = 1.

### 1.6 Initial step size (`cvHin`, `cvode.c:2180-2284`)
- Bounds: `hlb = HLB_FACTOR(100)·tround`, `hub = cvUpperBoundH0` = min(`HUB_FACTOR(0.1)·tdist`, `1/max_i |ẏ_i|/(0.1|y_i| + 1/ewt_i)`) (`2199-2200`, `2293-2329`; constants `cvode.c:122-125`). Trial `hg = sqrt(hlb·hub)` (`2202`).
- Up to `MAX_ITERS = 4` iterations: estimate `||ÿ||_WRMS` by one extra `f` evaluation at `y + hg·ẏ` (`cvYddNorm`, `2338-2355`); `hnew = sqrt(2/yddnrm)` if `yddnrm·hub² > 2` else `sqrt(hg·hub)` (`2253-2254`); stop when `0.5 < hnew/hg < 2` (`2262`).
- Final `h0 = H_BIAS(0.5)·hnew`, clipped to `[hlb, hub]` (`2277-2279`). Rationale: `h² ||ÿ||/2 ≈ 1` in WRMS units. Only called when `hin = 0` (`cvode.c:1176-1199`).

### 1.7 Other limits
- `MXSTEP_DEFAULT = 500` internal steps per `CVode` call (`cvode_impl.h:64`; check `cvode.c:1485-1489`, `CV_TOO_MUCH_WORK`); `MXHNIL = 10` warnings about `t + h == t` (`1513-1519`); `tolsf` too-much-accuracy check `uround·||zn[0]||_WRMS > 1` (`1497-1508`). `MXNCF = 10` convergence failures per step (`cvode_impl.h:127`).

### TORAX assessment (item 1)
- **Transfer directly:** predictor-corrector LTE with `tq[2] = 0.5` (BE) / `2/9` (BDF2, constant step); WRMS weights from `rtol, atol` per channel (T in keV, n in 1e19 m⁻³, ψ in Wb need separate `atol`); the `(6·dsm)^{−1/(q+1)}` law with the fixed-step band `[1, 1.5)` (avoids re-factorisations for tiny changes — precisely the concern with an expensive Jacobian) and the `0.25`/`0.2`/`0.1` shrink factors. All of this is scalar state that fits a `while_loop` carry `(y_n, y_{n−1}, h, h_prev, dsm_prev, nef, ncf, ...)` with fixed shapes.
- **Variable order** (q ≤ 5) is not worth porting: BDF ≥ 3 is not A-stable (repo guidance; STALD exists because of this, §7.3), and the order machinery adds control flow awkward in XLA. Variable-step BDF2 (coefficients from `tau[1..2]`, `cvSetBDF` q = 2 branch) is the sweet spot: 2nd order, L-stable, one implicit solve per step, same Jacobian structure as BE.
- The "never shrink after success" rule (η_min_fx = 0) is a cheap robustness trick versus TORAX's fixed or heuristic `dt ∝ dx²/max χ` (a *stability* heuristic irrelevant to an implicit method; the error-based rule adapts to physics, e.g. during a sawtooth crash).
- `cvHin` costs 2–8 RHS evaluations; the `h² ||ÿ|| ≈ 2` idea is a cleaner start than `dx²/χ`.
- Compile-time cost of the controller is negligible (scalar ops); the only branchy part is order selection — another reason to fix the order.

## 2. CVODE's Newton policy (modified Newton with lagged Jacobian)

### 2.1 Nonlinear system and residual
- Root-finding form: `F(y) = y − γ f(t_n, y) − a_n = 0`, `γ = h β_{n,0}` (doc eq. `CVODE_nonlinear`). Implementation `cvNlsResidual` (`src/cvode/cvode_nls.c:427-463`): `y = zn[0] + ycor`; `res = rl1·zn[1] + ycor − γ f(y)` (`458-459`), `rl1 = 1/l[1]`, `γ = h·rl1` (`cvode_impl.h:282-283`). One `f` evaluation per residual.
- Fixed-point form `cvNlsFPFunction` (`465-490`): `G = rl1·(h f(y) − zn[1])`.

### 2.2 Iteration limit and convergence test (`cvNlsConvTest`, `cvode_nls.c:343-396`)
- `NLS_MAXCOR = 3` (`:32`; installed at `:156`; `CVodeSetMaxNonlinIters`, `src/cvode/cvode_io.c:794`).
- `delnrm = ||δ_m||_WRMS` (`358`); for `m > 0`: **`crate = max(CRDOWN·crate, delnrm/delp)`**, `CRDOWN = 0.3` (`373-374`); **`dcon = delnrm · min(1, crate) / tol`**, `tol = tq[4] = nlscoef/tq[2]`, `nlscoef = CORTES = 0.1` (`376`; `cvode.c:127, 311`). Converged iff `dcon ≤ 1` (`378`). Interpretation (doc): `R||δ_m|| < ε_N ε` — the *estimated remaining iteration error in LTE units* must be < 10% of the error tolerance. For BE, `tol = 0.2` WRMS.
- Divergence: `m ≥ 1 && delnrm > RDIV·delp`, `RDIV = 2.0` → `SUN_NLS_CONV_RECVR` immediately (`386-389`).
- `crate` reset to 1 whenever the linear solver is set up (`cvNlsLSetup`, `:312`).

### 2.3 When is the linear solver set up / Jacobian re-evaluated?
- `cvNls` (`src/cvode/cvode.c:3100-3180`): `callSetup = (nflag == PREV_CONV_FAIL) || (nflag == PREV_ERR_FAIL) || nst == 0 || first_step_after_resize || nst ≥ nstlp + msbp || |gamrat − 1| > dgmax_lsetup` (`3115-3118`), `MSBP_DEFAULT = 20`, `DGMAX_LSETUP_DEFAULT = 0.3` (`cvode_impl.h:66-68`). `convfail = CV_NO_FAILURES` on first call or after an error-test failure, else `CV_FAIL_OTHER` (`3111-3113`).
- `cvLsSetup` (`src/cvode/cvode_ls.c:1556-1655`): `jbad = nst == 0 || first_step_after_resize || nst ≥ nstlj + msbj || (convfail == CV_FAIL_BAD_J && dgamma < dgmax_jbad) || convfail == CV_FAIL_OTHER` (`1585-1590`), `CVLS_MSBJ = 51`, `CVLS_DGMAX = 0.2` (`cvode_ls_impl.h:43-44`). If `jbad` is false the saved `J` is copied (`cvLsLinSys`, `1326-1340`); otherwise `J` is recomputed and saved (`1343-1383`). Then `A = I − γJ` (`SUNMatScaleAddI`, `1386`) and `SUNLinSolSetup` (LU) (`1637`).
- `SUNNonlinSol_Newton` retry logic (`src/sunnonlinsol/newton/sunnonlinsol_newton.c:361-373`): on a recoverable failure with `jcur == FALSE`, resets `ycor = 0`, sets `jbad = TRUE`, calls `LSetup` again — one nonlinear failure with a stale Jacobian costs a Jacobian re-evaluation but *not* a step reduction; only failure with a current Jacobian propagates to `cvHandleNFlag`.
- Doc summary (`doc/cvode/guide/source/Mathematics.rst`, "Nonlinear Solve"): matrix update "as infrequently as possible to balance the high costs of matrix operations against other costs": at start, > 20 steps, `|γ/γ̄ − 1| > 0.3`, after a convergence failure, after an error-test failure. Jacobian re-evaluation: at start, > 50 steps, convergence failure with outdated matrix and `|γ/γ̄ − 1| < 0.2`, or a convergence failure that forced a step-size reduction.

### 2.4 Response to nonlinear failure (`cvHandleNFlag`, `cvode.c:3355-3398`)
- Restore `zn`, `ncfn++`; unrecoverable codes propagate. Recoverable: `ncf++`, `etamax = 1`; if `ncf == maxncf (MXNCF = 10)` or `|h| ≤ hmin` → `CV_CONV_FAILURE`; else **`η = max(η_cf = 0.25, hmin/|h|)`**, rescale, `nflag = PREV_CONV_FAIL` (forces `callSetup` and `convfail = CV_FAIL_OTHER` → `jbad`), `PREDICT_AGAIN` (`3392-3397`).

### 2.5 The stale-γ correction (`cvLsSolve`, `cvode_ls.c:1800-1805`)
- With a matrix-based solver and BDF, if `gamrat ≠ 1` the correction is scaled: `b ← 2/(1 + gamrat) · b` (`scalesol`, default on for matrix-based; `CVodeSetLinearSolutionScaling`, `:430-449`). A matrix factored at `γ̄` is reused for `γ` within ±30% with first-order compensation.

### 2.6 Total cost per step (defaults, smooth regime)
- Per step attempt: 1 residual `f` at the predictor + 1 `f` per additional Newton iteration (≤ 3), 1 triangular back-solve per iteration, plus `SUNMatCopy` of the saved `J` and one LU *only* when `callSetup` triggers (≤ every 20 steps if `γ` stays within ±30%; with the `[1,1.5)` band typically only when the step actually changes).
- Jacobian *evaluations*: at most one per 51 steps unless failures occur; DQ dense costs `N` `f`-evals, DQ banded `mupper+mlower+1`.
- Example, N = 400, C = 4 (half-bandwidth 7): amortised Jacobian cost ≈ 15/51 ≈ 0.3 `f`-evals per step; total ≈ 2–4 `f`-evals and 2–4 back-solves per step. TORAX today: ≈ (Newton iterations) × (N JVPs + one dense LU) per step, e.g. 5 × (400 JVPs + LU).

### TORAX assessment (item 2)
- Adopt (a) the 3-iteration cap with the `crate` test; (b) stop on the *update* norm in WRMS units tied to the error tolerance (TORAX's `mean |residual| < 1e−5` is not scale-invariant across T/n/ψ, and the `1e−2` "coarse" fallback silently degrades accuracy — SUNDIALS never relaxes tolerance, it shrinks h); (c) the divergence test `||δ_m|| > 2||δ_{m−1}||` → shrink `h` by 0.25 rather than backtracking; (d) a *lagged Jacobian* carried in the loop state with `nstlj`, `nstlp`, `gammap` counters, recomputed only on `jbad`. In JAX: `J, LU = lax.cond(jbad, recompute, reuse, ...)`; XLA compiles both branches once, and on CPU `cond` executes only one, so no runtime cost when not taken; the `jacfwd` graph is compiled once regardless of how often it runs, so compile time is unaffected.
- Modified Newton with a stale J converges linearly; the `crate` test measures that rate. With NN critical-gradient transport the Jacobian changes abruptly when a gradient crosses threshold; the `RDIV` divergence test plus `η_cf = 0.25` is SUNDIALS' answer, and `SUNNonlinSol_Newton`'s "retry once with fresh J before shrinking h" is exactly the cheap-first escalation TORAX should use.
- The `2/(1+gamrat)` scaling is a one-line trick if dt changes but J/LU is reused (for BE, `γ = dt`).
- With the NN's non-smooth χ(∇T), a stale J is *sometimes better* (smoother) than an exact one — SUNDIALS' philosophy ("even a fairly poor approximation to the Jacobian ... can be surprisingly superior", CVODE Mathematics, "Preconditioning") supports lagging.

## 3. Linear solvers

### 3.1 `SUNLinSol_Dense` and `SUNLinSol_Band`
- Dense: LU with partial pivoting `SUNDlsMat_denseGETRF` (`src/sunlinsol/dense/sunlinsol_dense.c:146`), solve `denseGETRS` (`:180`). Cost `2N³/3` flops per factorisation.
- Band: `SUNDlsMat_bandGBTRF` (`src/sunlinsol/band/sunlinsol_band.c:155`) requires storage upper bandwidth `smu ≥ min(N−1, mu+ml)` for pivot fill-in (`:68-71`, `:150-152`); solve `bandGBTRS` (`:186`). Cost `O(N·ml·(mu+ml))`.
- Both are `SUNLINEARSOLVER_DIRECT`; CVODE passes `delta = 0` to them (`cvode_ls.c:1716`).

### 3.2 Difference-quotient Jacobians (`src/cvode/cvode_ls.c`)
- Dense (`cvLsDenseDQJac`, `1051-1130`): `srur = sqrt(U)` (`1085`), `fnorm = ||f||_WRMS`, `minInc = MIN_INC_MULT(1000)·|h|·U·N·fnorm` (or 1 if `fnorm = 0`) (`1087-1089`; `MIN_INC_MULT` at `:33`); **`inc_j = max(srur·|y_j|, minInc/ewt_j)`** (`1097`); sign flipped to respect inequality constraints (`1100-1111`); N evaluations of `f` (`1115`). Doc: `σ_j = max{√U |y_j|, σ_0/W_j}`.
- Banded (`cvLsBandDQJac`, `1143-1257`): `width = mlower + mupper + 1`, `ngroups = min(width, N)` (`1192-1193`); group `g` perturbs all columns `j ≡ g−1 (mod width)` simultaneously (`1199-1218`), one `f` evaluation per group (`1221`), then fills `J_{ij}` for `i ∈ [j−mupper, j+mlower]` (`1247-1252`). **Function evaluations = mupper + mlower + 1.**
- Matrix-free `Jv` (`cvLsDQJtimes`, `1267-1305`): **`σ = 1/||v||_WRMS`** (`1280`), `Jv = (f(y + σv) − f(y))/σ` (`1284-1302`), retried with `σ ← 0.25σ` up to `MAX_DQITERS = 3` times on recoverable failure (`1282-1295`, `:34`).
- System matrix `A = I − γJ` built by `cvLsLinSys` (`1312-1396`), with `savedJ` kept for reuse.

### 3.3 Krylov solvers and tolerances
- Defaults: `SUNSPGMR_MAXL_DEFAULT 5`, `SUNSPGMR_MAXRS_DEFAULT 0`, `SUNSPGMR_GSTYPE_DEFAULT SUN_MODIFIED_GS` (`include/sunlinsol/sunlinsol_spgmr.h:44-46`); `maxl = 5` also for SPFGMR/SPBCGS/SPTFQMR/PCG (`sunlinsol_spfgmr.h:43`, `sunlinsol_spbcgs.h:43`, `sunlinsol_sptfqmr.h:42`, `sunlinsol_pcg.h:40`).
- `SUNLinSolSolve_SPGMR` (`src/sunlinsol/spgmr/sunlinsol_spgmr.c:461-934`): scaled residual `r_norm = ||s1 P1⁻¹ r0||_2`; early exit if `r_norm ≤ delta` (`594`); Arnoldi with MGS/CGS (`723-730`), Givens QR of the Hessenberg (`734`), convergence when `rho ≤ delta` (`753`), restarts up to `max_restarts` (`620`, `845`); returns `SUNLS_RES_REDUCED` if not converged but residual reduced (`919`) else `SUNLS_CONV_FAIL` (`928`).
- CVODE tolerance (`cvLsSolve`, `cvode_ls.c:1692-1713`): **`deltar = eplifac · tq[4]`** (`1694`), `CVLS_EPLIN = 0.05` (`cvode_ls_impl.h:45`; `CVodeSetEpsLin`, `cvode_ls.c:348-369`); if `||b||_WRMS ≤ deltar` the correction is set to zero except on the first Newton iteration (`1702-1710`); L2 tolerance `delta = deltar · nrmfac`, `nrmfac = sqrt(N)` by default (`1712`; `CVodeSetLSNormFactor`, `373-398`); if the solver lacks scaling vectors, `delta /= ||w||_RMS` (`1757-1762`). `SUNLS_RES_REDUCED` accepted only on the first Newton iteration (`1837-1841`). Doc: `tol = C ε_L ε_N ε` with `C = √N`, `ε_L = 0.05`, `ε_N = 0.1`.
- IDA: `tol = nrmfac·eplifac·epsNewt` (`src/ida/ida_ls.c:1465`, `eplifac = 0.05` at `:207`); ARKODE: `deltar = eplifac·eRNrm` with `eRNrm = nlscoef` (`src/arkode/arkode_ls.c:3352`, `arkode_arkstep_nls.c:531`; `ARKLS_EPLIN 0.05`, `arkode_ls_impl.h:43`). v7.9.0 fix: "the factor provided by `ARKodeSetEpsLin` was scaled by 0.1" (`CHANGELOG.md`, 7.9.0 Bug Fixes).

### 3.4 Banded preconditioners and the diagonal solver
- `CVBandPre` (`src/cvode/cvode_bandpre.c`): banded DQ Jacobian with the same CPR grouping (`493-596`, `width = ml + mu + 1`), `P = I − γJ` (`412`), LU via `SUNLinSolSetup_Band` (`420`); reuses saved `J` when `jok` (`369-380`).
- `CVBBDPre` (`src/cvode/cvode_bbdpre.c`): MPI band-block-diagonal, DQ relative increment `dqrely = sqrt(U)` by default (`253`), separate DQ bandwidths `mudq/mldq` and retained `mukeep/mlkeep` (`109-114`).
- `CVDiag` (`src/cvode/cvode_diag.c`): diagonal Jacobian approximation from one perturbed `f` evaluation with `FRACT = 0.1` of the functional-iteration correction (`:31`, `317-318`).

### TORAX assessment (item 3)
- **Bandwidth arithmetic for TORAX:** with unknown index `i = cell·C + channel` (cell-major), a nearest-neighbour stencil couples `|i − j| ≤ 2C − 1`, so `mu = ml = 2C − 1` (7 for C = 4, 3 for C = 2), `width = 4C − 1` (15 / 7). Channel-major ordering would give bandwidth ≈ `(C−1)·ncells` — avoid. Banded LU is `O(N·(2C−1)·(4C−2))` ≈ 1.6e5 flops for N = 800, C = 4, versus `2N³/3 ≈ 3.4e8` dense.
- **Coloured JVPs:** the CPR trick in `cvLsBandDQJac` is exactly `jax.jvp(f, (y,), (e_g,))` with seed `e_g = Σ_{j ≡ g mod width} e_j`, 15 JVPs instead of N. **Caveat:** CPR assumes exact bandedness. TORAX's Gaussian smoothing of χ and integral constraints create global couplings; grouping then *aliases* far-column derivatives into band entries (not merely omits them). Options: (i) compute the "local" Jacobian with smoothing frozen at the predictor (exact for the local part) and let modified Newton absorb the inexactness (`crate` test), refreshing the full dense `jacfwd` only on `jbad` (≤ every 51 steps); (ii) Sherman–Morrison/low-rank correction for the few global rows; (iii) keep dense `jacfwd` but lag it (already ≥ 10× fewer evaluations).
- Krylov (SPGMR, maxl = 5) with `CVBandPre` is the SUNDIALS recipe for *large* N; at N ≤ 800 a direct banded/dense solve is cheaper and deterministic (no iteration count → fixed-shape friendly). Matrix-free Newton–Krylov with `jax.jvp` would cost ~15 JVPs per step (5 GMRES × 3 Newton) *and* converge worse than a factored band matrix.
- `minInc` and `sqrt(U)|y_j|` increments are irrelevant with AD, except as a reminder that DQ Jacobians of a noisy NN surrogate would be unusable; AD (jacfwd/JVP) is a genuine advantage TORAX has over SUNDIALS' defaults.

## 4. Nonlinear solvers: fixed-point/Anderson, Newton, KINSOL

### 4.1 `SUNNonlinSol_FixedPoint` (`src/sunnonlinsol/fixedpoint/sunnonlinsol_fixedpoint.c`)
- Construction requires the depth `m` (`SUNNonlinSol_FixedPoint(y, m, sunctx)`); defaults `damping = FALSE`, `beta = 1`, `maxiters = 3` (`129-136`); damping via `SUNNonlinSolSetDamping_FixedPoint(NLS, beta)` with `0 < beta < 1` (`418-438`).
- Iteration (`212-334`): `yprev = ycor`; `gy = G(ycor)`; if `m == 0` plain `ycor = gy` (`265-269`) else `AndersonAccelerate` (`272-273`); `delta = ycor − yprev`; integrator convergence test on `delta` (`280-285`); `SUN_NLS_CONV_RECVR` after `maxiters` (`330-333`).
- `AndersonAccelerate` (`545-737`): cyclic slot `i_pt = (iter−1) mod maa` (`574`); `fv = gval − xold`, `dg = gval − gold`, `df = fv − fold` (`577-584`); first iteration plain FP (`592-597`); QR of `ΔF` built incrementally by MGS (`611-638`); once full, the left-most column is deleted by Givens rotations on `R` and `Q` (`639-697`); least-squares `γ = R⁻¹ Qᵀ fv` by back substitution (`699-716`); update `x = gval − Σ γ_i dg_i − (1−β)(fv − Σ γ_i df_i)` (`704-734`). Memory: 5 + 3m vectors (`739-789`).
- Doc (`doc/shared/sunnonlinsol/SUNNonlinSol_FixedPoint.rst`): Walker–Ni formulation; "The acceleration subspace size m is required when constructing". CVODE doc: fixed-point is "for nonstiff systems" (`doc/cvode/guide/source/Mathematics.rst:136-140`). ARKODE doc: "While a Newton-based iteration is the default solver in ARKODE due to its increased robustness on very stiff problems, we strongly recommend that users also consider the fixed-point solver when attempting a new problem" (`doc/arkode/guide/source/Mathematics.rst:1846-1855`).
- ARKODE has **no built-in `maa` default** (the depth lives in the NLS object); shipped examples mostly use `m = 0` or small `m` (e.g. `SUNNonlinSol_FixedPoint(y, 4, ...)`).
- **`SUNNonlinSol_Auto`** (7.8.0, `doc/shared/sunnonlinsol/SUNNonlinSol_Auto.rst`): Nørsett switching FP→Newton when `R ≥ α = 0.8` (`R ← max{0.3R, ||δ_m||/||δ_{m−1}||}`) and Newton→FP when `stiffr = ||F(y^m)||/||δ_m|| < β = 2.0` for `newt_to_fp_delay = 10` solves; `stiffr` computed at `sunnonlinsol_newton.c:336-352`.

### 4.2 `SUNNonlinSol_Newton` (`src/sunnonlinsol/newton/sunnonlinsol_newton.c`)
- `maxiters = 3` (`123`). Solve (`215-388`): residual `Sys(ycor, delta)`; if `callLSetup` → `LSetup(jbad, &jcur)`; loop: `delta ← −delta`, `LSolve(delta)`, `ycor += delta`, `CTest(NLS, ycor, delta, tol, w)` (`274-290`); on `SUN_NLS_CONTINUE` and `curiter < maxiters` re-evaluate residual; on recoverable failure with `!jcur && LSetup`: `nconvfails++`, `ycor = 0`, `jbad = TRUE`, retry (`361-373`). The convergence test is an integrator callback (`cvNlsConvTest`, `idaNlsConvTest`, `arkStep_NlsConvTest`).

### 4.3 KINSOL (`src/kinsol/kinsol.c`, `kinsol_impl.h`)
- Defaults (`kinsol_impl.h:47-53`; `kinsol.c:292-313`): `mxiter = 200`, `msbset = 10` (Jacobian setup every 10 nonlinear iterations), `msbset_sub = 5`, `mxnbcf = 10` (β-condition failures), `ω_min = 1e−5`, `ω_max = 0.9`, `sqrt_relfunc = sqrt(U)`, **`scsteptol = U^{2/3} ≈ 3.7e−11`**, **`fnormtol = U^{1/3} ≈ 6.1e−6`**, `etaflag = KIN_ETACHOICE1`, `eta = 0.1` (constant choice), `eta_alpha = 2`, `eta_gamma = 0.9`; `mxnewtstep` default `1000·||u_0||_{D_u}` (L2), at least 1 (`kinsol.c:1127-1134`).
- Main loop `KINSol` (`448-766`): inexact tolerance `eps = (η + U)·||F||` with floor `0.01·fnormtol` (`583-586`, `628-636`); strategies `KIN_NONE` (`644-660`), `KIN_LINESEARCH` (`661-684`), `KIN_PICARD` (`598-617`), `KIN_FP` (`521-562`). Jacobian setup gate `sthrsh > 1.5` (`KINLinSolDrv`, `1254`), set to 2 at start / after `msbset` iterations / after failures (`1244-1247`, `1287`, `KINStop 1833, 1869, 1929`); for inexact Newton `sthrsh = ||λδ||_{D_u,∞}` (`1898`), so J is refreshed when the scaled step exceeds 1.5 (doc "Jacobian information update strategy").
- **`KINLineSearch`** (`1448-1763`): `alpha = 1e−4`, `beta = 0.9` (`1461-1462`); cap `pnorm ≤ mxnewtstep` (`1477-1484`); constraints via `KINConstraint` (`0.9·min-quotient`, `1777-1803`); α-condition `f1(u + rl·p) ≤ f1(u) + α·slpi·rl` with `f1 = ½||F||²_{D_F}`, `slpi = Fᵀ(D_F² Jp)` (`1556`, `1572-1581`); backtracking quadratic first then cubic (`1585-1609`), `rl ← max(0.1·rl, min(rltmp, 0.5·rl))` (`1610-1617`); minimum `rlmin = scsteptol/||p/(1/D_u + |u|)||_∞` (`1557-1558`, `1634-1641`); then the **β-condition** `f1 ≥ f1(u) + β·slpi·rl` with step doubling up to `rlmax = mxnewtstep/||p||` (`1647-1681`) and bisection between the last α-satisfying and β-violating values (`1683-1741`); β-failures counted in `nbcf`, abort at `nbcf > mxnbcf = 10` (`1737`, `679-683`).
- Stopping (`KINStop`, `1821-1964`): `||F||_{D_F,∞} ≤ fnormtol` → success (`1855`); `||u_{n+1} − u_n||_{scaled,∞} ≤ scsteptol` → `KIN_STEP_LT_STPTOL` unless J is stale (then refresh and continue) (`1857-1877`); five consecutive max-length steps → `KIN_MXNEWT_5X_EXCEEDED` (`1886-1889`); residual monitoring for modified Newton with `ω = min(ω_min·e^{max(0, ||F||/fnormtol − 1)}, ω_max)` (`1912-1920`).
- Forcing terms (`KINForcingTerm`, `1984-2028`): Eisenstat–Walker choice 1 `η = | ||F(u_{n+1})|| − ||F + Jδ|| | / ||F||` with safeguard `η_prev^{(1+√5)/2}`, choice 2 `η = γ (||F_{n+1}||/||F_n||)^α`; bounds `η ∈ [1e−4, 0.9]`.
- DQ Jacobian (`kinsol_ls.c:816-817`): `inc = sqrt_relfunc·max(|u_j|, 1/uscale_j)·sign(u_j)`; `Jv` (`947-1000`): Brown–Saad `σ = sign·√U·max(|uᵀv|, ||v||_1)/||v||²` on scaled vectors. Linear tol `tol = eps·tol_fac` (`1226`).
- Picard (`KINPicardAA`, `2222-2381`): `G(u) = u − L⁻¹F(u)` with `L` the user's fixed matrix (`KINPicardFcnEval`, `2397-2444`), optional damping and AA (`2274-2332`); FP (`KINFP`, `2453-2601`) with `||G(u) − u||_{D_F,∞} ≤ tolfac·fnormtol` (`2565-2584`, `tolfac = β` when damped). KINSOL's AA (`AndersonAcc`, `2683-2957`) also supports delayed start (`kin_delay_aa`), user depth/damping functions and low-sync QR variants (`KINSetOrthAA`, `kinsol_io.c:182`).
- KINSOL vs PETSc SNES `bt` (background knowledge, not verified in this repo): both follow Dennis–Schnabel cubic backtracking with `α = 1e−4`; KINSOL additionally enforces the curvature (β = 0.9) condition, caps the scaled step at `mxnewtstep`, and limits β-failures to 10; PETSc's `bt` is Armijo-only.

### TORAX assessment (item 4)
- **Anderson for the 'linear' mode:** TORAX's Picard/predictor-corrector with frozen coefficients is a preconditioned fixed-point map `G(u) = u − L(u_k)⁻¹F(u)` in KINSOL's Picard sense. AA with `m = 3–5` and damping `β ∈ [0.5, 1)` typically cuts iteration counts several-fold on such maps; the QR-update implementation is entirely fixed-shape (m columns, cyclic slot, Givens delete) and cheap (`O(mN)` per iteration + an `m×m` triangular solve) — ideal inside a JAX `while_loop`. Pereverzev–Corrigan stabilisation is orthogonal and can stay.
- **Depth/iterations:** SUNDIALS' integrators cap FP at the same `maxiters = 3` as Newton (`cvode_nls.c:156`); for a Picard map on stiff transport this is too few — set `maxiters` ≈ 10–30 as TORAX does, and use the WRMS update-norm test with the `crate` estimate (works for FP too; `SUNNonlinSol_Auto` uses it to detect FP stagnation at `R ≥ 0.8`).
- **Line search inside time stepping:** SUNDIALS deliberately does not do it; the predictor + step reduction keeps Newton in its convergence basin and each shrink costs 1 predictor + ≤3 iterations. TORAX's Newton backtracking (halving) is closer to `IDACalcIC`'s line search (§5.4), which SUNDIALS reserves for the *initial-condition* problem where there is no step to shrink. If TORAX keeps a line search, KINSOL's form (α = 1e−4 sufficient-decrease on ½||F||², quadratic/cubic interpolation, `rl ≥ 0.1·rl_prev`, β-failure counter) is more disciplined than plain halving and is a bounded `while_loop`.
- KINSOL's `fnormtol = U^{1/3}` and `scsteptol = U^{2/3}` defaults are scaled max-norms; TORAX's mean-abs residual `1e−5` mixes units. Use `D_F` (residual scaling per channel) and `D_u` scaling explicitly.

## 5. IDA/IDAS: DAEs, algebraic components, `cj`-scaled Jacobian

### 5.1 Formulation and Jacobian
- Residual `F(t, y, ẏ) = 0`; BDF in fixed-leading-coefficient form; residual callback sets `yy = yypredict + ycor`, `yp = yppredict + cj·ycor` (`src/ida/ida_nls.c:316-318`). Jacobian **`J = ∂F/∂y + cj ∂F/∂ẏ`** (doc `IDA_DAE_Jacobian`; `cj = −α_s/h`, `ida.c:2686`; for BDF1 `cj = 1/h`, `ida.c:2502`).
- DQ increments (band, `src/ida/ida_ls.c:1124-1127`): `inc = max(√U·max(|y_j|, |h·ẏ_j|), 1/ewt_j)·sign(h ẏ_j)`, perturbing both `y_j` and `ẏ_j += cj·inc`; `Jv` (`1207-1255`) with `σ = nrmfac·dqincfac` for SPGMR/SPFGMR else `dqincfac/||v||_WRMS`, `dqincfac = 1` (`ida_ls.c:208`).

### 5.2 Jacobian reuse controlled by the `cj` ratio (`IDANls`, `ida.c:2730-2807`)
- `cjratio = cj/cjold`; `callLSetup` if `cjratio < (1−dcj)/(1+dcj)` or `> (1+dcj)/(1−dcj)` with **`DCJ_DEFAULT = 0.25` → thresholds 0.6 and 1.667** (`2753-2759`; `ida_impl.h:69-70`; `IDASetDeltaCjLSetup`, `ida_io.c:43-59`; doc: "α/ᾱ < 3/5 or α/ᾱ > 5/3"). Also at the first step and after failures (`2742-2746`; `idaNlsLSetup` resets `cjold = cj`, `cjratio = 1`, `ss = 20`, `ida_nls.c:271-274`). `ss` is set to 100 whenever `cj` changed since the last step (`2760`). IDA has *no* `msbp/msbj` step counter — reuse is governed purely by `cj` drift and failures.
- Solution scaling as in CVODE: `b ← 2/(1 + cjratio)·b` when `cjratio ≠ 1` (`ida_ls.c:1582-1584`, `scalesol` on for matrix-based solvers, `:280`).

### 5.3 Newton convergence test (`idaNlsConvTest`, `ida_nls.c:347-389`)
- `MAXIT = 4` iterations (`:29`), `RATEMAX = 0.9` (`:30-31`), `epcon = EPCON = 0.33` (`ida.c:183`, `IDASetNonlinConvCoef`).
- `m == 0`: converged if `||δ_1|| ≤ 1e−4·toldel` (noise guard, `373-376`); `m > 0`: `rate = (||δ_m||/||δ_1||)^{1/m}`, fail if `rate > 0.9` (`380-381`), `ss = rate/(1 − rate)` (`382`); converged if `ss·||δ_m|| ≤ tol = epsNewt` (`385`). Doc: "S = 20 initially and whenever J or P is updated, reset to S = 100 on a step with α ≠ ᾱ".

### 5.4 Algebraic variables: `IDASetId`, `IDASetSuppressAlg`, `IDACalcIC`
- `IDASetId(ida_mem, id)` stores the 1/0 differential/algebraic mask (`src/ida/ida_io.c:524-560`); `IDASetSuppressAlg(TRUE)` (`505-520`) makes every error-norm call use `N_VWrmsNormMask(x, w, id)` (`IDAWrmsNorm`, `ida.c:3503-3512`) — used in `IDATestError` (`2969-2970`, `2984-2985`, `2998-2999`) and order selection (`3299-3300`), but **not** in the Newton convergence norm (`mask = SUNFALSE` "when the call is made from the nonlinear solver", `3499`). Doc: "A user option is available by which the algebraic components of the error vector are omitted from the test".
- **`IDACalcIC(ida_mem, icopt, tout1)`** (`src/ida/ida_ic.c:107-292`): `IDA_YA_YDP_INIT = 1` (given `y_d`, solve for `y_a` and `ẏ_d`) or `IDA_Y_INIT = 2` (given `ẏ`, solve for all `y`) (`include/ida/ida.h:41-42`). Sets `epsNewt = epiccon = 0.01·EPCON = 0.0033` (`ida_ic.c:202`; `ida.c:347`), an artificial step `hic = 0.001·tdist` reduced so that `hic·||ẏ||_WRMS ≤ 0.5` (`213-216`), `cj = 1/hic` (`221`), then up to `nwt = 2` weight updates × `mxnh = MAXNH = 5` step reductions (`hic *= 0.1`, `251`) × `MAXNJ = 4` Jacobian setups (`IDANlsIC`, `346`) × `MAXNI = 10` Newton iterations (`IDANewtonIC`, `448`), each with the Armijo line search `IDALineSrch` (`519-615`): `ALPHALS = 1e−4` (`:47`), halving `λ /= 2` (`600`), `minlam = steptol/||δ||` with `steptol = U^{2/3}` (`555`; `ida.c:353`), at most `MAXBACKS = 100` backtracks (`569`; `ida.c:184`). Constraints honoured with `0.99·min-quotient` scaling (`545-549`). Convergence in `||J⁻¹F||_WRMS` (`IDAfnorm`, `635`), slow-convergence retry if `rate ≤ ICRATEMAX = 0.9` or the norm dropped by 10× (`480-486`).

### 5.5 Step/order control (`ida.c`)
- Constants (`ida_impl.h:52-72`; `ida.c:178-184`): `MAXORD = 5`, `MXSTEP = 500`, `ETA_MAX_FX = 2`, `ETA_MIN_FX = 1`, `ETA_MAX = 2`, `ETA_MIN = 0.5`, `ETA_LOW = 0.9`, `ETA_MIN_EF = 0.25`, `ETA_CF = 0.25`, `MXNCF = 10`, `MXNEF = 10`.
- Error test (`IDATestError`, `2961-3029`): `err_k = σ_k·||ee||`, fail if `ck·||ee||_WRMS > 1` (`3027`), `ck = max(|α_k + α_s − α_0|, α_k)` (`2690-2691`) — max of the LTE constant and the interpolation-error constant (doc `IDA_lerrtest`). Order lowered *before* the test if `max(T(k−1), T(k−2)) ≤ T(k)` (`3008`) or, at k = 2, `T(1) ≤ T(2)/2` (`3016`), with `T(q') = (q'+1)·ELTE(q')`.
- On error failure (`IDAHandleNFlag`, `3159-3204`): 1st → `η = 0.9·(2·err + 1e−4)^{−1/(k+1)}` clipped to `[0.25, 0.9]`; 2nd → `η = 0.25`; 3rd+ → order 1 and `η = 0.25`; give up after 10.
- After success (`IDACompleteStep`, `3236-3399`): "phase 0" doubles h and raises order every step until the first failure/order-5 (`3262-3271`); otherwise `η = (2·err_new + 1e−4)^{−1/(k+1)}` (`3349`), grow only if `η ≥ 2` (to at most 2), shrink only if `η ≤ 1` (to `[0.5, 0.9]`) (`3351-3368`). Order raise requires k+1 constant steps (`ns`, `3288`) and `T(k+1) < T(k)` (`3319-3321`).
- Initial step (`IDASolve`, `1187-1193`): `h = 0.001·tdist`, reduced so that `h·||ẏ||_WRMS ≤ 0.5`.

### TORAX assessment (item 5)
- TORAX's row-replacement rows (pedestal, prescribed profiles) make the system an index-1 DAE; IDA's design says: (i) **mask algebraic rows out of the error norm** (their "error" is meaningless) but keep them in the Newton norm; (ii) the Jacobian block for algebraic rows is `∂F/∂y` (no `cj`), so a lagged Jacobian factored at `cj_old` is only reusable while `cj/cj_old ∈ [0.6, 1.67]` — with BE `cj = 1/dt`, dt may drift by −40%/+67% before a re-factorisation is forced. This is the DAE-aware version of CVODE's `dgmax = 0.3` and is the rule TORAX should implement if it lags J across dt changes.
- `IDACalcIC` is the reference for "start from an inconsistent state" (after a pedestal/profile switch or restart): its artificial `hic` and `cj = 1/hic` trick reuses the time-stepping Jacobian; the tolerance `0.0033` is *tighter* than the stepping tolerance `0.33` because IC errors persist. TORAX's initial state after boundary-condition changes would benefit from a similar consistency solve rather than letting the first implicit step absorb the inconsistency.
- IDA's Newton test (rate-based `ss = R/(1−R)`, fail at `R > 0.9`, ≤4 iterations) is a slightly more tolerant cousin of CVODE's; the `1e−4·toldel` first-iteration guard avoids evaluating a convergence rate on noise — relevant when the NN residual has ~1e−6 relative noise.
- IDA's "double h and raise order every step until failure" start phase is aggressive; for TORAX (BE/BDF2 fixed order) prefer CVODE's `η ≤ 10` growth with the 1.5 band.

## 6. ARKODE (ARKStep IMEX/DIRK, controllers, LSRKStep/ExtSTS, MRIStep)

### 6.1 ARKStep structure and error estimate
- Stages `z_i = y_{n−1} + h Σ_{j<i} A^E_{ij} f^E(z_j) + h Σ_{j≤i} A^I_{ij} f^I(z_j)` with embedded `ỹ_n` (`doc/arkode/guide/source/Mathematics.rst:325-441`, eq. `ARKODE_ARK`). `arkStep_TakeStep_Z` (`src/arkode/arkode_arkstep.c:1674-2241`): a stage is implicit iff `|A^I_{ii}| > TINY = 1e−10` (`1735`, `1924`); `γ = h·A^I_{ii}`, `gamrat = γ/γ_p` (`arkStep_StageSetup`, `3122-3127`); residual `r = z_c − γ f^I(z_p + z_c) − sdata` (`arkode_arkstep_nls.c:600-607`).
- Error estimate `yerr = h Σ_j (b_j − d_j) F_j`, **`dsm = ||yerr||_WRMS`** (`arkode_arkstep.c:3339-3346, 3382`); test `dsm ≤ 1` (`arkCheckTemporalError`, `src/arkode/arkode.c:3469`).
- Default order `Q_DEFAULT = 4` (`src/arkode/arkode_impl.h:65`). Default tables (`include/arkode/arkode_arkstep.h:48-73`): implicit-only q = 1 `BACKWARD_EULER_1_1` (no embedding), **q = 2 `GKC21_ESDIRK_3_1_2`**, q = 3 `ESDIRK325L2SA_5_2_3`, q = 4 `ESDIRK436L2SA_6_3_4`, q = 5 `ESDIRK547L2SA2_7_4_5`; IMEX pairs q = 2 `GKC21` ERK+ESDIRK, q = 3 `ARK324L2SA`, q = 4 `ARK437L2SA`, q = 5 `ARK548L2SAb`. ### 6.5 LSRKStep (RKC/RKL super-time-stepping) and ExtSTS (new in 7.9.0)
- Methods `ARKODE_LSRK_RKC_2`, `ARKODE_LSRK_RKL_2` (2nd order, adaptive, embedded) and SSP variants (`include/arkode/arkode_lsrkstep.h:40-44`). Doc: "STS methods ... designed for stiff problems characterized by having Jacobians with eigenvalues that have large real and small imaginary parts ... The extent of this stability region is proportional to the square of the number of stages used" (`Mathematics.rst:540-547`).
- Defaults (`src/arkode/arkode_lsrkstep_impl.h:33-38`): `STAGE_MAX_LIMIT 200`, `DOM_EIG_SAFETY 1.01`, `RKC_DAMPING 2/13`, `DOM_EIG_FREQ 25` steps.
- **Stage count** (`src/arkode/arkode_lsrkstep.c`): RKC `coefz = 1.5/(1 − (2/15)·damping)` ≈ 1.531 (`601-602`); `zR = h·λ_R`; **`s = max(2, ceil(sqrt(1 − coefz·zR)))`** (`622-625`), i.e. `s ≈ sqrt(1 + 1.53·h|λ_R|)`; RKL **`s = ceil((sqrt(9 + 8·h|λ_R|) − 1)/2)`** ≈ `sqrt(2 h|λ|)` (`1070-1076`). If `s > stage_max_limit` and adaptive: `h_max = safety·(s_max² − 1)/(coefz·|λ_R|)` and the step is retried (`631-648`). A stability-function check (Chebyshev/Legendre polynomial on the ellipse) can add stages (`665-700`, `3028-3170`).
- Dominant eigenvalue: user function `LSRKStepSetDomEigFn` or a `SUNDomEigEstimator` (power iteration defaults: `100` warm-up iterations, `rel_tol 0.005`, `max_iters 100`, `src/sundomeigest/power/sundomeigest_power.c:38-42`); re-estimated every `dom_eig_freq = 25` steps (unless `const_Jac`) or after any failed step (`lsrkStep_DomEigUpdateLogic`, `2893-2910`); `λ_R·h` must be ≤ `√U` (`2982-2987`); values inflated by `dom_eig_safety` (`2996-2997`).
- **ExtSTS** (`src/arkode/arkode_mristep_extsts.c`, `MRIStepCreateExtSTS(fd, fe, fi, ...)`, `include/arkode/arkode_mristep.h:216`): wraps an LSRKStep STS integrator (max stages raised to 10000, `:43`; interpolation disabled, `:53`) as the MRI "fast" solver for the diffusion term `f^D`, with default couplings `ARKODE_IMEX_MRI_GARK_GKC21` (implicit or IMEX slow part) or `ARKODE_MRI_GARK_EXP_GKC21` (explicit-only) (`140-151`); each fast IVP is solved with **one fixed STS step** (`258-260`, `301-307`). Doc: "designed for problems ẏ = f^D + f^E + f^I ... f^D ... super time stepping (e.g., diffusion terms) ... f^I ... implicit (e.g., reaction terms)"; "ExtSTS methods are at most second order" (`Mathematics.rst:833-885`; `CHANGELOG.md` 7.9.0).

### 6.6 MRIStep (multirate)
- Splitting `ẏ = f^E + f^I + f^F`, slow explicit/implicit with `h^S`, fast with `h^F ≪ h^S` (`Mathematics.rst:570-676`); MRI-GARK / IMEX-MRI-GARK / IMEX-MRI-SR / MERK families; implicit slow stages supported **only in "solve-decoupled" form** (a standard DIRK update where `Δc^S_i = 0`) (`:733-740`). Multirate controllers: decoupled or `h^S`–`Tol` (MRIHTol) (`:1334-1440`).

### TORAX assessment (item 6)
- **One-step L-stable 2nd order with an embedded error estimate** is the most natural upgrade of TORAX's θ-method: `GKC21_ESDIRK_3_1_2` (explicit first stage + 2 implicit stages of the *same* structure `z − γ f(z) = a`, embedding order 1) or `TRBDF2_3_3_2`. Each implicit stage is one TORAX-style nonlinear solve with `γ = h·A_ii` replacing `dt`; the Jacobian `I − γJ` can be shared across stages when `A_ii` is constant (ESDIRK/SDIRK: `gamrat = 1` within a step), so lagging works across stages. Cost ≈ 2 implicit solves per step versus 1 for BE, but 2nd order with error control; the 3rd/4th-order ESDIRK tables (4–5 implicit stages) are unlikely to pay off with NN-transport accuracy limits.
- **Predictor:** ARKODE's default *trivial* predictor is the conservative choice for stiff/positivity-sensitive problems — TORAX's current behaviour (start Newton from `y_n`) matches it. The variable-order/cutoff extrapolation predictors use the last step's Hermite interpolant (needs `y_{n−1}, f_{n−1}` in the carry) — cheap and worth trying for stage predictions.
- **`nlscoef = 0.1` and the error test:** Newton stops when the estimated remaining error is 10% of the tolerance; the embedded-error test then decides acceptance. This is the coupling TORAX lacks (its Newton tolerance and dt heuristic are unrelated).
- **`SetLinear` semantics = TORAX's 'linear' solver:** if TORAX linearises with coefficients frozen at the predictor, ARKODE would treat this as `linear, timedepend = 1`: one linear solve per stage with the matrix rebuilt every stage — the cost structure of TORAX's predictor-corrector mode, but without Picard sweeps. The `deduce_rhs` option (`f^I(z_i) = (z_c − sdata)/γ`) saves one NN evaluation per stage.
- **Controllers:** for a 2nd-order method with 1st-order embedding, the I controller gives `h' = 0.9·h·dsm^{−1/2}` (safety 0.9, `ord = p+1 = 2`); PI `(0.8, −0.31)` or H0211 damp oscillations in `h` that pure I control shows on problems with sharp transitions (sawteeth). All are 3–5 scalar carries; set the `[lbound, ubound]` band to `[1, 1.5]` (CVODE-like) to avoid re-factorising for tiny changes.
- **STS/ExtSTS honesty check:** for TORAX diffusion `|λ| ≈ 4χ_max/Δx²`; with `χ_max ~ 10–100 m²/s`, `Δx ~ 0.02 m` → `|λ| ~ 1e5–1e6 s⁻¹`; at `h = 1e−3 s`, RKC needs `s ≈ sqrt(1 + 1.53·10³..10⁴) ≈ 40–125` stages, each an NN transport evaluation, plus dominant-eigenvalue estimation (power iteration: 100 warm-up JVPs by default, though a JAX user could supply `λ_R` analytically from `max χ/Δx²` via `LSRKStepSetDomEigFn`). Compared with 2–4 NN evaluations + a banded LU per implicit step this is 10–50× more transport-model work; stability is linear-analysis-based, so the critical-gradient nonlinearity (χ jumping by orders of magnitude within a step) risks under-estimated `λ` (safety factor only 1.01) and step rejections. STS is only competitive when Jacobians/linear solves are unavailable or N is huge — neither holds for TORAX. ExtSTS could put sources implicit and diffusion explicit, but TORAX's stiffness *is* the diffusion, so this inverts the sensible split. Verdict: not applicable, except as a Jacobian-free fallback.
- **MRIStep:** ψ evolves slowly (resistive time) while T evolves fast, but MRI methods gain when the *fast* part is cheap/explicit and the *slow* part is expensive; in TORAX the fast part (T, n with NN transport) is the expensive stiff part and the whole system is solved implicitly at the fast scale anyway. Since N ≤ 800, including ψ in every implicit solve is negligible; what MRI would buy is a principled way to update ψ (and its `q`-profile feedback on transport) every `k` steps with error control (`MRIHTol`). Verdict: not worth the complexity; if ψ lagging is desired, an IMEX-MRI-GARK "solve-decoupled" structure is the formal template, but a simple `k`-step lag with the slow error monitored by the embedded estimate is adequate.
- `ARKodeSetLSetupFrequency(msbp < 0)` = "refactor every solve" is the knob equivalent to TORAX's current behaviour; the docs' `msbp = 20` / `msbj = 51` defaults are the counter-proposal.

## 7. Other high-impact features

### 7.1 Inequality constraints / positivity (`CVodeSetConstraints`, `cvCheckConstraints`, `cvode.c:3197-3320`)
- After a converged Newton step, `N_VConstrMask` flags violations (`3206`). A candidate correction `v` is built (`3244-3250`): strict constraints (`|c| = 2`) are shifted by `0.1/ewt_i` (`tmp = −0.1·c/ewt`, `3246-3247`), and `y − 0.1·tmp` is masked to failed entries. If `||v||_WRMS ≤ tq[4]` (the Newton tolerance) the correction is *applied*: the correction/predictor is zeroed where constraints failed and shifted by the saved adjustment (`3256-3280`, `constraint_corrections++`). Otherwise restore, `η = max(0.9·N_VMinQuotient(zn[0], zn[0] − y), 0.1, hmin/|h|)` (`3305-3313`), `nflag = PREV_CONV_FAIL`, retry; give up at `MAX_CONSTRAINT_FAILS = 10` (`cvode_impl.h:130`) or `hmin`. DQ Jacobians flip perturbation signs to stay feasible (`cvode_ls.c:1100-1111`). ARKODE (`arkCheckConstraints`, `arkode.c:3360`) and IDA (`IDACheckConstraints`, `ida.c:2809`) share the design; KINSOL scales the step by `0.9·min-quotient` (`KINConstraint`).
- **TORAX:** implement as (i) mask of violated T/n entries; (ii) if the WRMS size of the needed clamp is below the Newton tolerance, clamp and accept; (iii) else shrink dt by the linearised distance to the boundary (`0.9·min_i y_i/(y_pred,i − y_i)`), floor 0.1. All fixed-shape vector ops.

### 7.2 Step-count limit
- `CVodeSetMaxNumSteps` default `MXSTEP_DEFAULT = 500` steps per output interval (`cvode_impl.h:64`; ARKODE `arkode_impl.h:67`; IDA `ida_impl.h:56`). The repo guidance flags this as the most common "failure" users hit (`.agents/skills/sundials-guide/SKILL.md`, "Choose initial settings").
- **TORAX:** a per-output-interval step cap is the natural bound for a JAX `while_loop` (or `fori_loop` with early-exit mask) — it also bounds trace work.

### 7.3 Stability limit detection (STALD)
- `CVodeSetStabLimDet` (`cvode_io.c:251`); `cvBDFStab` (`cvode.c:3921-3981`) collects scaled derivative data at `q ≥ 3`, calls `cvSLdet` after `nscon ≥ q + 5` steps (`3956`); constants `rrcut = 0.98`, `vrrtol = 1e−4`, `vrrt2 = 5e−4`, `sqtol = 1e−3`, `rrtol = 1e−2` (`4033-4037`); on detection the order is reduced with `η = η_{q−1}` (`3959-3971`). Doc: appropriate for "semi-discretized PDEs ... with advection and diffusion, but with advection dominating"; overhead 2–7%.
- **TORAX:** irrelevant (pure-diffusion decay modes; with BE/BDF2 the issue does not arise).

### 7.4 Root-finding / event detection (`CVodeRootInit`, `cvode.c:833`; `cvRootfind`, `4620-4850`)
- Sign changes of `g_i(t, y)` checked over each step; roots located by a modified secant/Illinois iteration to `ttol = 100·U·(|t_n| + |h|)` (`4347`, `4439`, `4518`) using the Nordsieck interpolant (`CVodeGetDky`); `iroots`, `rootdir` filters, `gactive` to skip functions that are zero at the start. Doc: "finds only roots of odd multiplicity"; the most-likely-first root is chosen by the largest `|g_i(t_hi)|/|g_i(t_hi) − g_i(t_lo)|`. Returns `CV_ROOT_RETURN`; integration resumes with `CVodeReInit`.
- **TORAX (sawtooth trigger, L–H transition):** events are located *between* steps by interpolation, then the integrator restarts at the event with a fresh history (order 1, `cvHin`). For BE the interpolant is linear, so bisection/secant on `g(t_n + θh, y_n + θ(y_{n+1} − y_n))` for a few iterations is consistent with the method order; resetting the step-size controller after the event (as CVODE does) avoids error-test thrash after a crash. In JAX this is a bounded secant loop on scalars plus a "reset carry" branch.

### 7.5 Sensitivities and adjoints (CVODES / SUNAdjoint)
- Forward sensitivities: `CVodeSensInit(cvode_mem, Ns, ism, fS, yS0)` with `ism ∈ {CV_SIMULTANEOUS, CV_STAGGERED, CV_STAGGERED1}` (`include/cvodes/cvodes.h:45-47`); the staggered corrector reuses the state's `M` (doc `CVODES_stgr_iterations`, `doc/cvodes/guide/source/Mathematics.rst:931-951`); DQ sensitivity RHS (`cvSensRhs1InternalDQ`, `src/cvodes/cvodes.c:9790+`): `δ = sqrt(max(rtol, U))`, `Δp = p̄·δ`, `Δy = 1/max(||s||_WRMS·p̄, 1/δ)/p̄`, centred directional derivative by default (`DQtype = CV_CENTERED`, `DQrhomax = 0`, `:597-598`); sensitivities excluded from the error test by default (`errconS = FALSE`, `:602`).
- Adjoint (CVODES): **continuous** adjoint `λ̇ = −f_yᵀλ` integrated backward with checkpointing: `CVodeAdjInit(cvode_mem, steps, interp)` sets `N_d = steps` between checkpoints and `interp ∈ {CV_HERMITE, CV_POLYNOMIAL}` (`src/cvodes/cvodea.c:104-200`); `CVodeF` stores a checkpoint every `N_d` steps (`586-601`) and forces a Jacobian re-evaluation before each ("to avoid storing Jacobian-related data at each checkpoint", doc "Checkpointing scheme"); the polynomial interpolant "requires only half of the memory storage of the cubic Hermite interpolation and is more accurate".
- **Discrete** adjoint (`SUNAdjointStepper`, `src/sundials/sundials_adjointstepper.c`; `SUNAdjointCheckpointScheme_Fixed`): "ARKODE provides discrete adjoint methods (discretize-then-differentiate)" (`doc/shared/sunadjoint/SUNAdjoint_Introduction.rst`), but `ARKStepCreateAdjointStepper` requires **fixed step** (`arkode_arkstep.c:3588-3593`), **explicit RK only** (`fi == NULL`, `3595-3607`; "Implicit methods are not yet supported by the adjoint stepper", `3689-3694`), no relaxation/mass matrix/constraints.
- **TORAX:** JAX already gives the discrete adjoint of the step function, with `jax.checkpoint` playing the role of `SUNAdjointCheckpointScheme_Fixed`. Two SUNDIALS lessons carry over: (i) the discrete adjoint of an *adaptive* integrator is only well-defined if the step sequence is frozen (SUNDIALS refuses adaptive steps for its discrete adjoint) — so TORAX should `stop_gradient` the controller decisions (accept/reject, `h`) and, for reproducible gradients, record and replay the step sequence; (ii) CVODES' forced Jacobian refresh at checkpoints is the analogue of making the recomputed forward segment bit-reproducible — relevant if TORAX lags Jacobians in a rematerialised loop (the lag counters must be part of the checkpointed carry).

### 7.6 Projection onto invariants (`CVodeSetProjFn`, `src/cvode/cvode_proj.c:47`; `cvDoProjection`, `:279`)
- After the corrector, the user projection computes `y_n = argmin ||y − ỹ||_WRMS s.t. g(t_n, y) = 0` via a least-norm Newton correction (doc eq. `CVODE_proj`, `CVODE_leastnorm`); options `CVodeSetProjFrequency` (default every step), `CVodeSetProjErrEst`, `CVodeSetEpsProj`, `CVodeSetProjFailEta` (`cvode_proj.c:106-232`); the projected correction is folded into the Nordsieck update (`cvCompleteStep`, `cvode.c:3582-3587`); BDF only.
- **TORAX:** integral constraints (prescribed total current, particle inventory) currently enforced by row replacement could instead be a post-solve projection (rank-few least-norm correction) — keeps the Jacobian banded and matches SUNDIALS' "project then error-test" ordering.

### 7.7 Resizing / mesh changes
- `ARKodeResize(arkode_mem, y0, hscale, t0, resize_fn, data)` (`src/arkode/arkode.c:84-204`): one-step methods only need the current `y`; `hscale` rescales the next step. CVODE's `CVodeResizeHistory` (`src/cvode/cvode_resize.c:194`) rebuilds the Nordsieck array from a supplied history of `(t, y, f)` by divided differences (`36-89`).
- **TORAX:** fixed radial grid, so not needed; if adaptive meshes ever appear, one-step methods are strictly simpler.

### 7.8 What the user guides say about inexact Newton and lagging (quotes)
- CVODE: "In the case of a matrix-based linear solver, the default Newton iteration is a Modified Newton iteration, in that the iteration matrix M is fixed throughout the nonlinear iterations. ... With the default Newton iteration, the matrix M and preconditioner matrix P are updated as infrequently as possible to balance the high costs of matrix operations against other costs." (`doc/cvode/guide/source/Mathematics.rst`, "Nonlinear Solve").
- IDA: "The above strategy balances the high cost of frequent matrix evaluations and preprocessing with the slow convergence due to infrequent updates. To reduce storage costs on an update, Jacobian information is always reevaluated from scratch." (`doc/ida/guide/source/Mathematics.rst`, "Nonlinear Solve").
- ARKODE: "for linear solvers and preconditioners that do not rely on costly matrix construction and factorization operations ... it may be more efficient to update these structures more frequently than the above heuristics specify, since the increased rate of linear/nonlinear solver convergence may more than account for the additional cost of Jacobian/preconditioner construction." (`doc/arkode/guide/source/Mathematics.rst:2036-2047`).
- Preconditioning: "the preconditioner may use a very crude approximation, as long as it captures the dominant numerical feature(s) of the system. We have found that the combination of a preconditioner with the Newton-Krylov iteration, using even a fairly poor approximation to the Jacobian, can be surprisingly superior to using the same matrix without Krylov acceleration (i.e., a modified Newton iteration)" (CVODE and IDA Mathematics, "Preconditioning").
- Linear tolerance ratio: "Smaller values of ε_L are typically useful for strongly nonlinear or very stiff ODE systems, while easier ODE systems may benefit from a value closer to 1. The default values are ε_L = 0.05 and ε_N = 0.1" (CVODE/ARKODE Mathematics).
- Repo guidance on BDF vs DIRK for parabolic problems: "When comparing CV_BDF and implicit ARKStep, remember that BDF methods above order 2 are not A-stable. If the user needs higher-order stiff decay, stronger damping of parasitic fast modes, or a parabolic diffusion problem is behaving poorly under high-order BDF, either cap BDF order at 2 or move the recommendation toward an appropriate DIRK table in ARKStep." (`.agents/skills/sundials-guide/SKILL.md`).

## 9. Synthesis: a SUNDIALS-informed redesign sketch for TORAX

1. **Method:** keep one-step structure; use variable-step BDF2 (CVODE q = 2 branch of `cvSetBDF`) or `GKC21_ESDIRK_3_1_2`/`TRBDF2` (ARKODE). Both are L-stable and 2nd order; the ESDIRK route gives an embedded error estimate without step history; BDF2 gives one implicit solve per step but needs `y_{n−1}` and `h_{n−1}` in the carry (and BE for the first step, as CVODE does).
2. **Error control:** `dsm = tq[2]·||y − y_pred||_WRMS` (BE 0.5, BDF2 2/9) or `||h Σ (b−d) F||_WRMS`; accept if ≤ 1; `η = 1/((6 dsm)^{1/(q+1)} + 1e−6)` with band `[1, 1.5)`, growth ≤ 10, shrink ≥ 0.1 (0.2 after two failures), `η_cf = 0.25` on Newton failure; per-channel `rtol/atol`.
3. **Newton:** trivial (or extrapolation) predictor; ≤ 3 iterations; stop when `min(1, crate)·||δ||_WRMS ≤ 0.1/tq[2]`; divergence if `||δ_m|| > 2||δ_{m−1}||`; Jacobian lagged with `(nstlj, nstlp, γ_p, jcur)` in the carry, refreshed on `jbad`; correction scaled by `2/(1+γ/γ_p)` when reusing an LU; algebraic rows masked out of the error norm; positivity via the constraint clamp/shrink logic; on failure with a stale J, refresh J first, only then shrink `h`.
4. **Jacobian:** 4C − 1 coloured JVPs into a band matrix with global couplings frozen at the predictor (or dense `jacfwd` every ≤ 51 steps); banded LU (`smu = 2(2C−1)`); dense LU is affordable only at N ≲ 400.
5. **'Linear' mode:** Picard map + Anderson (m = 3–5, damping) with the same WRMS/crate stopping test.
6. **Events:** bracket `g` over the step, secant/bisection on the linear interpolant, then reset the controller state (order 1, `cvHin`-style step) after the event.
7. **AD:** stop gradients through `h`, accept/reject and Jacobian-refresh flags; checkpoint the full carry (including lag counters) so the rematerialised forward pass is identical.
8. **Not recommended for TORAX:** variable order BDF ≥ 3 / STALD, Krylov + band preconditioners (N too small), STS/ExtSTS (diffusion is the stiff nonlinearity; s ≈ 40–125 NN evaluations per step), MRIStep (whole system is cheap enough to solve implicitly at the fast scale).
